## Three findings that matter more than the score

### 1. The benchmarks leaked their own answers (fixed)
Every source file contained a comment naming the bug (`// VULNERABLE: external call before state update`). Any prior "benchmark" run was invalid — the agent read the answer key. Fixed by `blind_benchmark.sh`, which strips all comments and refuses to copy ground-truth.json into the audited tree. `selfcheck.sh` now regression-guards that the stripper removes every answer keyword.

### 2. The Sui benchmark's ground truth was wrong (corrected, not gamed)
`sui-shared-object-race` asserted an EVM-style "two concurrent txns both read the old counter → lost update" race. **That cannot happen on Sui**: consensus serializes all transactions taking a shared object as input. The breadth agent correctly refused to report the race and instead found a *real* bug the oracle had missed — deposited `Balance<SUI>` accumulates with no withdraw/claim path, so all funds are permanently locked. Actions taken:
- Corrected the oracle: real fund-lock is now `must_detect`; the disputed race is retained `must_detect:false, disputed:true` with an `_oracle_review` note.
- Codified the semantics so future Sui audits don't invent the race: new `platform-quirks/sui.md` #1 + `refuted/INDEX.md` RF-12.
This is an accuracy *gain* (a wrong oracle produces wrong regression signal), distinct from coaching the metric — the fund-lock is independently verifiable by reading the file.

### 3. The one real precision miss
On `sui-shared-object-race` the agent flagged the read-only `get_reward_estimate()` view (the FP trap) as "misleading-view-divergence" — because no claim path exists. That reasoning is downstream of the real fund-lock bug, not an independent issue; reporting it separately is over-reporting. Counts as a false positive. This is the kind of low-severity over-report the pipeline's later realism-filter / dedup stages are designed to absorb, but at the raw breadth layer it is a precision cost.

## Calibration signal: breadth over-escalates severity

4 of 6 findings were rated one tier above ground truth (reentrancy, unchecked-return, missing-signer each +1). On single-function toy contracts a full drain is arguably Critical, so the gap is partly benchmark conservatism — but the consistent upward bias is real and is exactly what the downstream `rules/realism-filter.md` + `rules/severity-decision-tree.md` (Phase 5d) exist to correct. Not changed here; flagged for monitoring.

## Caveats (do not over-read this baseline)
- Single breadth pass per benchmark, sonnet, no depth/Nemesis/verify — this measures the *cheapest* tier, not the full pipeline. Real audits run far more.
- 6 toy contracts (≤60 lines, one bug each) are a smoke test, not a representative corpus. They prove the agents catch textbook classes and mostly respect FP traps; they say little about novel business-logic depth.
- No Aptos, Stellar, or C++ benchmark exists yet — those trees are unmeasured. Coverage gap logged.
